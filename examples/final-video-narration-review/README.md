# 最终视频旁白离线校对

给负责产品演示、培训视频和小团队剪辑的人：用最终MP4提取声音，在本地转写，再按时间点核产品名、数字和使用条件。能播放不等于说对；转写有差异也不等于原旁白有错。

## 先拿走两张表

- [空白校对表](./review-template.csv)：另存后填写自己的最终视频，不上传敏感音轨。
- [实际校对例表](./review-example.csv)：自有合成教学视频的三个原句和邻近转写，均保留“待听审”。不是客户案例。
- [本次运行摘要](./observed-run.json)：模型、参数、时间和原始文件摘要；不含视频、权重或收费核心。

CSV用UTF-8保存。Excel可从“数据→从文本/CSV”导入并选择UTF-8，不要直接把原有字幕覆盖成识别结果。状态只在实际听过对应音轨后填写；未听清写待核，并保留时间点。

## 本地怎样跑

前置条件：本机已有FFmpeg、官方whisper.cpp命令行运行文件、匹配的多语言`ggml-base.bin`；有处理该视频的权限。以下是Windows PowerShell示例，路径与文件名换成自己的，文件名有空格时保留引号。

```powershell
ffmpeg -i "final.mp4" -vn -ar 16000 -ac 1 -c:a pcm_s16le "review.wav"
.\whisper-cli.exe -m ".\ggml-base.bin" -f ".\review.wav" -l zh -ng -t 4 -otxt -osrt -oj -of ".\review"
```

输入必须来自最终导出MP4，不用配音源文件或时间线预览代替。转换得到16kHz、单声道、16位PCM WAV；第二条命令使用中文、CPU四线程，输出TXT、SRT、JSON。中文不要误用仅英语的`base.en`。本次没有把原稿作为初始提示喂给识别器。

TXT用于读全文，SRT用于定位时间，JSON便于整理。工具不会替你直接判定正确与否，也不会仅凭这条命令输出本目录的校对CSV：将原句、时间点、邻近转写整理进表，再听对应音轨并填写结论。ASR分段不一定与原字幕一一对应。

从[官方whisper.cpp仓库](https://github.com/ggml-org/whisper.cpp)查安装与用法，从[官方模型托管](https://huggingface.co/ggerganov/whisper.cpp)查模型。下载前核来源、适用系统和许可，运行前核摘要；本公开资料不分发二进制或模型。找不到模型先核路径，输入格式不符先核WAV，不要一报错就重复下载或换大模型。

## 实际跑到了哪一步

2026年10月14日，从一条自有机加工排程教学视频最终导出物提取音轨：视频238.133333秒，音频238.0663125秒。用多语言base模型、中文、CPU四线程转写一次，退出0，转写调用耗时30.86771秒，得到37个片段。

这是本机本例的转写时间，不含下载、转换、制表或人工听审，不是速度承诺。35条源字幕都有至少0.3秒的转写片段时间重叠，只表示时间覆盖，不证明逐字正确、逐句同步或整片已经通过。6条重点行来自产品名、运行条件与数字关键词标记，不是6个已确认错误。

例表中的Capafy被转写成“可不可以”、Python被转写成“拍作”，交期数字也出现异常。base模型可能误识别，配音也可能含糊；本例尚未完成人工全听，所以这些只用于定位，不裁定原音错误，不自动改字幕。

## 每次最终导出后检查三件事

| 角色 | 先做什么 | 留什么证据 |
|---|---|---|
| 剪辑者 | 确认最终文件有声、可完整解码与播放 | 最终MP4、版本或哈希、解码记录 |
| 复核者 | 按时间点听产品名、数字、否定词和使用条件 | 原句、转写、时间点、实际听审结论 |
| 发布者 | 从输入看到调用和结果，核版本、入口和使用条件 | 最终演示及保存状态；草稿与公开分开 |

一人兼三职也分三次检查。改旁白后重新检查最终导出物，不能沿用旧音轨回执。转写再准，也不能补出不存在的操作画面；讲解卡和日志回放应如实标明，不冒充连续录屏。

本次音轨只在本地处理，没有上传云端。第三方工具是否联网、宿主费用和素材隐私，应按实际安装与使用情况另核。本文为LeanEdge原创实操整理，含AI辅助；表格可自行填写使用并保留来源，不获得第三方软件、模型或付费产品的转售授权。工具与演示没有自动获客、成交或收入保证。
