# Dify 单库密钥权限检查配套

给 AI 客服接知识库，既要确认售后库能访问，也要确认其他库被拒绝。这份 LeanEdge 原创配套提供文章中的三次 GET 请求示例、离线测试和空白凭据登记表。先做不联网的练习，再由获授权的维护者在测试资料上核验真实部署。

## 先跑离线练习

下载本目录的文件，保存在同一文件夹。需要 Python 3，使用标准库，不用安装依赖，不用账号或 API 密钥。在该文件夹运行：

```powershell
python -m unittest -v test_scope_check.py
```

测试用假地址 `https://example.invalid/v1`、假密钥和模拟响应运行原示例。10 项测试检查 GET 方法、15 秒超时、路径、错误处理及输出；它们不连接 Dify，也不能证明你的实例权限配置正确。

其中一项模拟正确范围，得到下面的**教学输出**，不是实际服务器记录：

```text
/datasets/allowed-demo/documents 200
/datasets/other-demo/documents 403
/datasets 403
```

## 真实部署怎样检查

`scope-check.py` 是文章原代码，独立运行时会联网。只在你有权维护的部署上使用，先建两个装有测试资料的库，并创建只绑定允许库的新密钥。不要拿陌生企业或含敏感资料的库做试验。

在本机安全配置中设置以下环境变量。密钥不要写入脚本、命令历史、登记表、截图或 GitHub。

| 环境变量 | 内容 |
|---|---|
| `DIFY_BASE_URL` | 部署实际显示的知识库服务 API 地址，包含相应前缀；不要使用控制台首页地址 |
| `DIFY_DATASET_KEY` | 新创建、绑定允许库的服务 API 密钥 |
| `DIFY_ALLOWED_ID` | 该密钥获准访问的测试库 ID |
| `DIFY_OTHER_ID` | 同一工作区中另一测试库 ID；你本人也须有测试授权 |

配置完成后才运行联网示例：

```powershell
python scope-check.py
```

脚本只发送三个 GET 请求、打印路径和状态码，不读取响应正文，不发送写入或删除请求。它**不会自动判断通过，也不以退出码表示授权验收成功**。应由维护者逐行核对：

| 请求 | 预期 | 异常时的动作 |
|---|---|---|
| 允许库文档列表 | 成功，教学示例为 200 | 先核部署地址、密钥和允许库 ID |
| 另一库文档列表 | 范围拒绝，官方说明为 403 | 返回 200 时暂停交接，核密钥是否仍为工作区范围 |
| 不带库 ID 的全局列表 | 范围拒绝，官方说明为 403 | 返回 200 时同样复核密钥范围 |

401、404、超时都不是“权限正确”的证据。网络异常会直接中止示例，不会自动重试；403 也可能来自网关策略，须结合部署配置确认是预期的范围拒绝。三个请求只能检查这些端点，不是全接口安全审计或只读权限认证：**GET 是本次检查的方法，不代表密钥本身没有写权限。**

## 交接时留什么

用 [credential-register.csv](credential-register.csv) 记录负责人、用途、允许库、凭据别名、创建日期、复查触发条件和三次结果。表内不填完整密钥；路径和库 ID 也可能是内部信息，实际记录留在你自己的受控位置，不贴到公开 Issue。

旧密钥撤销前先查依赖它的应用。新密钥完成允许与拒绝两侧核验、接收方确认替换后，再撤销旧凭据并验证失效。角色变化、资料分级变化和应用停用都可触发复查。
