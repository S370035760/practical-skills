# 别让自动化把缺信息和重复咨询一起往下送：拿走3路分诊代码，先跑9个本地样本

给维护咨询表单、运营待办和自动化流程的人：先确认请求能不能接手，再决定要不要进入回复流程。这里公开 LeanEdge 原创教学样例的代码、输入、完整预期输出和本地检查脚本；不需要模型密钥，也不发送任何消息。

这是2026-10-12 LeanEdge n8n实操稿的配套资料，不是另一款付费Coze技能，不是完整CRM或导入即用的n8n工作流。当前验收覆盖纯JavaScript逻辑，未部署n8n实例或连接客户系统。

## 先看输入，会得到什么

三项必填字段为非空字符串：`request_id`、`contact`、`need`。样例联系人是教学占位值，不是真实客户资料，也不是可投递地址。

| 输入情况 | 输出 route | 输出 reason | 下游建议 |
|---|---|---|---|
| 三字段完整，当前批次首次出现 | REVIEW | 空字符串 | 人工核对、形成待办 |
| 缺字段、空字符串或字段类型不对 | FIX | 缺项字段名 | 补资料，暂不进入发送 |
| 同一批次完整请求的ID重复 | HOLD | duplicate_in_batch | 保留记录，人工核对 |

[下载完整输入](./sample-input.json)与[逐条预期输出](./expected-output.json)。四条样例的结果依次是 `REVIEW → FIX → HOLD → FIX`。原始JSON业务字段保留，并新增 `route`、`reason`；不处理二进制数据或其他n8n元数据。

## 先在本机检查，别急着接生产

已有支持这些Node内置模块的Node.js即可，本地验收使用Node v25.2.1。下载本目录中的五个文件，保持放在同一目录，然后运行：

```bash
node verify.cjs
```

它读取 `code-node.js`，提供模拟的 `$input.all()`，核对字段和路由。无需 `npm install`，没有联网、付费模型、发消息或客户数据上传动作。**不要直接运行 `node code-node.js`**：该文件是n8n Code节点正文，必须由测试脚本或节点执行。

检查包含完整请求、缺联系人、同批重复、空ID、数字联系人、ID两侧空格、不完整请求之后补齐、跨次执行边界，以及下载样例的逐字段比对，共9个场景。结果为 `status: PASS`、`scenarios: 9`；这是本机逻辑检查，不等于n8n端到端验收或实际业务收益。

## 放进n8n时怎样接

1. 在测试工作流副本中添加Code节点，选择JavaScript与 **Run Once for All Items**。
2. 把 [code-node.js](./code-node.js) 的全部内容贴进去。上游每条输入的业务字段应在 `json` 内。
3. 先用四条教学输入测试，核对输出与上表一致。
4. 在下游用条件分支判断 `route`：REVIEW接人工待办，FIX接补资料队列，HOLD接复核队列。不要把三个出口重新连到同一个无条件发送节点。
5. 先检查输入字段与分支，再用你有权使用的脱敏样本验证凭据、接收对象、下游返回值和失败重试。本文不提供已验证的工作流JSON导入包。

模式与输入方法见 [n8n官方Code节点文档](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.code/) 和 [官方当前节点输入说明](https://docs.n8n.io/code/builtin/current-node-input/)，2026-10-12核对。这里没有复制n8n源码，也不改变其许可。

## 这些边界一定要先知道

- `Set`只在本次执行内保存。跨批重跑、Webhook重投和并发执行不会自动去重；测试刻意验证“分两次执行相同ID，仍各为REVIEW”。
- 去重比较会去掉ID两侧空格，但原始ID字段不会被改写。大小写仍敏感；同一个业务ID应由上游规范定义，不能凭联系人相同就认定重复。
- 三字段完整只表示通过这段字段检查，不证明联系人真实、已同意联系、需求有效或消息已送达。
- 第一次不完整的请求不占用ID；后来的完整请求可进入REVIEW。完整请求占用后，同批下一条相同ID转HOLD。
- 生产需要持久化唯一约束和状态设计。`待处理/发送中/成功/失败`应分开；不能把“登记过ID”当成“发送成功”，否则会吞掉合法重试。
- 需要HTTP调用、文件读写或实际发送时，另按官方对应节点配置。这个样例不完成这些动作，也没有为你验证当前版本、凭据或生产连线。
