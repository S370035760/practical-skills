# 预算有限，先把一个质量异常跟到验证通过

面向中小制造企业的免费教学资料。它解决的是异常记录、责任追踪和验证留痕，不是完整质量管理体系、认证文件或安全专业方案。

## 下载

- [12列空白记录表 CSV](quality-exception-template.csv)
- [异常跟踪闭环教学图 PNG](quality-exception-loop.png)

CSV 是 UTF-8；用 Excel 的“数据→从文本/CSV”导入并选择 UTF-8。第二行全是“教学待填写”，只是填写提示：复制成工作表后先清空提示再记录实际信息。样本数和异常数填非负整数，异常数不得大于样本数；不要把提示文字用于计算。

## 先怎样使用

1. 从一个已经发生的异常开始。先核对现行合格标准、版本、抽样数量、时间和批次口径；不要事后为了好看更换判定标准。
2. 记录事实和证据，不把“操作员不认真”当成已查明原因。公开交流前去掉客户名称、订单、人员身份和商业秘密。
3. 有权限的人决定必要的临时遏制措施。**遏制不等于根因解决**；根据风险另做原因调查、纠正措施及执行记录，必要时由专业人员处理。
4. 指定具体负责人和期限，在实施前约定如何验证效果。验证范围、样本量和观察时间要与实际风险匹配，本资料没有通用“连续三批合格就能关闭”的规则。
5. 取得预先约定的验证证据再由有权限的人评审关闭；失败则继续调查和处理，不能只重复临时隔离。保留修改与验证历史。

## 使用边界：不要把图当完整程序

流程图展示最低限度的跟踪回路，**没有展开原因调查、纠正措施执行、变更控制和批准权限**。实际工作应补充“标准版本/抽样口径、原因假设与验证、纠正措施、执行证据、批准人、关闭日期”等字段，必要时用独立记录关联事件编号。十二列只是起步模板，不代表这些工作可以省略。

频次排序不是根因证明；写了措施不是验证关闭。高严重度、安全、法规或客户关键特性的风险不能仅按件数排序处理。涉及适用法规、客户特殊要求或强制认证时，须另外确定并满足这些要求。
